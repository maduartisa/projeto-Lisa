## 2. PERFIS DE USUÁRIO (RBAC) E NÍVEIS DE ACESSO

1. **Administrador (`ADMIN`):**
   - Gestão global de configurações, parametrização de sistemas e integração de IA.
   - Acesso total a relatórios financeiros, dashboards executivos e logs de auditoria.
   - Gestão e controle de permissões de usuários.

2. **Operador de Balcão (`OPERADOR_BALCAO`):**
   - Acesso ao Ponto de Venda Web (PDV) para consulta e reserva de estoque.
   - Aprovação e conversão de orçamentos pré-qualificados pelo Chatbot de IA.
   - Gestão de pedidos das modalidades *Clique e Retire* e *Delivery Express*[cite: 3].
   - Emissão e confirmação de vendas no balcão[cite: 1].

3. **Gerente de Estoque (`GERENTE_ESTOQUE`):**
   - Entrada e conferência de mercadorias.
   - Ajustes manuais de inventário e lançamento de perdas/avariados.
   - Definição de níveis de estoque mínimo e monitoramento de alertas.

4. **Cliente Final (`CLIENTE_FINAL` - Acesso Externo via Web/WhatsApp):**
   - Navegação no Catálogo Digital em nuvem[cite: 3].
   - Solicitação de orçamentos e consulta automatizada de estoque/preços 24 horas por dia[cite: 2, 3].
   - Acompanhamento do status de pedidos e escolha do método de entrega/retirada[cite: 2, 3].

## 3. PILHA TECNOLÓGICA E INFRAESTRUTURA AWS

### 3.1. Arquitetura de Software
- **Backend Framework:** Python com FastAPI (Assíncrono, Pydantic v2).
- **ORM & Banco de Dados:** ORM Assíncrono com banco relacional PostgreSQL (gerenciado via AWS RDS em sub-rede privada).
- **Frontend Admin / PDV:** Next.js / React com Tailwind CSS.
- **Frontend Catálogo:** Next.js otimizado para PWA (*Mobile-First*).
- **Autenticação:** JSON Web Tokens (JWT) com Access Token e Refresh Token, além de suporte a controle de acesso baseado em papéis (RBAC).
- **Orquestrador de IA:** Integração com LLM via API com suporte nativo a *Function Calling* para execução controlada de consultas de estoque e montagem de orçamentos.

### 3.2. Infraestrutura AWS
- **AWS VPC:** Sub-redes públicas (para Load Balancers) e privadas (para aplicação e banco de dados).
- **AWS EC2:** Instância tipo Graviton/ARM rodando containers Docker para a aplicação backend, catálogo e gateway de mensageria.
- **AWS RDS:** Instância PostgreSQL gerenciada com rotinas automáticas de backup diário e retenção programada.
- **AWS S3:** Buckets privados para armazenamento de imagens do catálogo, notas fiscais e comprovantes de pagamento.
- **AWS IAM:** Políticas de acesso com menor privilégio para comunicação entre os serviços.

## 4. REQUISITOS FUNCIONAIS DOS MÓDULOS

### 4.1. Módulo de Autenticação e Segurança
- Autenticação segura por e-mail e senha com suporte a encriptação avançada.
- Validação contínua de permissões por rotas na API (Middleware de Segurança).
- Registro detalhado de logs de auditoria contendo ID do usuário, tipo de ação, recurso modificado, endereço IP e data/hora.

### 4.2. Módulo de Gestão de Estoque e Produtos
- Cadastro completo de produtos: SKU, nome, categoria, subcategoria, descrição técnica, preço de custo, preço de venda, estoque atual, estoque mínimo, unidade de medida e imagem.
- Categorização organizada para itens de Limpeza, Tratamento de Piscina, Descartáveis, Utilidades e Automação.
- Registro histórico de todas as movimentações: Entradas por Compra, Saídas por Venda, Perdas por Avaria e Ajustes de Inventário.
- Sistema automatizado de alertas para produtos que atingirem o nível igual ou inferior ao estoque mínimo.

### 4.3. Módulo de Ponto de Venda (PDV Balcão) & E-commerce Omnicanal
- Interface de busca rápida no balcão por SKU ou nome do produto com atualização instantânea de estoque.
- Suporte a múltiplas modalidades de checkout:
  - *Atendimento Presencial no Balcão*[cite: 1].
  - *Clique e Retire:* Agendamento de horário de busca no balcão com validação via código PIN[cite: 2, 3].
  - *Delivery Express Local:* Cálculo de taxas e rotas de entrega para Taguatinga e regiões do DF via parceiros de logística[cite: 3].
- Suporte a múltiplas formas de pagamento: PIX, Cartão de Crédito, Cartão de Débito, Dinheiro e Faturado/Convênio.
- Baixa automática e atômica no estoque no momento em que a venda for concluída.

### 4.4. Módulo de Atendimento Automatizado via WhatsApp (IA Comercial)
- Recebimento de mensagens via Webhooks seguros.
- Triagem inteligente do atendimento:
  - Consulta automática de disponibilidade e preços no estoque[cite: 2].
  - Montagem e envio de resumos de orçamentos com validade temporária[cite: 2, 3].
  - Fornecimento de dados da loja (localização, horários e políticas de entrega)[cite: 2].
- Transferência humanizada: Identificação de solicitações complexas e redirecionamento do atendimento para os colaboradores do balcão.

### 4.5. Módulo de CRM Preditivo e Recompra
- Motor de análise histórica de consumo para identificar padrões de compras recorrentes.
- Agendamento diário de tarefas em segundo plano para identificação de clientes no período de renovação de estoque.
- Disparo de notificações personalizadas via WhatsApp sugerindo a recompra programada de insumos de limpeza e piscina.

### 4.6. Módulo de Relatórios e Dashboards Executivos
- Visualização em tempo real de KPIs de Faturamento (Diário, Mensal, Anual).
- Indicadores de Ticket Médio e volume de vendas segmentados por canal (Balcão, WhatsApp, Catálogo Web).
- Ranking dos produtos mais vendidos (Curva ABC).
- Relatórios de valoração de estoque (Custo vs. Venda) e listagem de itens esgotados ou com baixo estoque.
- Métrica de desempenho do assistente de IA: taxa de conversão de orçamentos gerados em vendas pagas.

## 5. DIRETRIZES TÉCNICAS E REGRAS DE IMPLEMENTAÇÃO

1. **Tipagem e Validação de Dados:** Todos os payloads de entrada e saída das APIs devem ser validados via esquemas estritos com tipagem explícita.
2. **Tratamento de Exceções:** Retorno padronizado de códigos de erro HTTP com mensagens estruturadas no padrão JSON.
3. **Consistência de Dados:** Operações que envolvem saída de estoque e geração de faturamento devem executar sob transações atômicas no banco de dados para evitar inconsistências ou estoque negativo.
4. **Documentação Viva:** O código-fonte backend deve manter anotações suficientes para a geração automática da documentação OpenAPI/Swagger.
5. **Estrutura Modular:** O projeto deve respeitar a divisão clara entre camada de apresentação/rotas, camada de regras de negócio/serviços, camada de acesso a dados/modelos e utilitários globais.
